### 1. ★ 本轮修的真 bug:探针在骗人

`agent-bridge` 的 `probeBackends()` 是给设置面板看"哪些 agent CLI 能用"的。
它的实现只看**文件在不在**:

```
hermes        ✓ 已就绪:D:\...\hermes.cmd
codex         ✗ 已安装但未登录(缺 ~/.codex/auth.json)
command-code  ✓ 已就绪:D:\...\command-code.cmd      ← 这里在撒谎
claude        ✗ 未安装
opencode      ✗ 未安装
```

**真跑一下 command-code 才知道**:

```
$ command-code -p "hi"
stdout: Updated 1.63.0 → 1.88.0
stderr: Error: Insufficient credits for Command Code.
exit code: 10
```

它**装了、登录了(`~/.commandcode/auth.json` 存在)、但额度耗尽**。
静态探针查不到账号状态 —— 额度不是文件,只有真跑才知道。

用户看到的却是"✓ 已就绪",点下去才炸。**这比直接报错更糟**:
设置面板把不可用的后端显示成可用的,用户会以为是自己的用法问题。

> 讽刺的是,`agent-bridge.ts` 自己的文件头注释就写着
> "**可用性必须实测**,不能只看 `which`" —— 但 probeBackends 恰恰只做了静态检查。

#### 修法:让运行结果反哺探针

1. **新增 `detectUnavailableReason(text)`** —— 认出三类"用不了"的信号:
   - 额度不足:`insufficient credits` / `quota exceeded`
   - 未登录 / 认证失败:`not logged in` / `authentication failed`
   - 需要交互式 TTY:`interactive mode requires a TTY`

2. **新增运行时判定缓存**(`recordRuntimeVerdict` / `getRuntimeVerdict`):
   `runAgent` 结束时按后端 id 记下"这次跑通了"或"这次因为额度挂了 + 具体原因"。
   探针**优先读这份缓存,覆盖静态结论**。TTL 30 分钟 —— 额度不会秒级变,
   但用户可能刚充值,过期后自动回到静态判断。

3. **`command-code` 增加登录态静态预检** —— 缺 `~/.commandcode/auth.json` 就直接报未登录,
   不用等到跑完才失败。

#### 踩坑记录

| 坑 | 现象 | 根因 |
|---|---|---|
| 探针只看文件 | command-code 报"已就绪",实跑退出码 10 | 额度是账号状态,文件里查不到 |
| 错误在 stderr 不在 stdout | `command-code -p "hi"` stdout 只有 "Updated 1.63.0 → 1.88.0" | 自更新提示占了 stdout;真错误在 stderr → 判据要同时看两股流 |
| 漏了 `-p` 参数 | 手动验证时报 "Interactive mode requires a TTY terminal." | `command-code` 不带 `-p` 就是交互模式 → 探针里的 `buildArgs` 才是对的,手测时得跟它一致 |
| 非零退出码不等于"后端不可用" | 任务本身失败也会退出码 1 | 必须先问"是不是额度/登录问题",不能把所有非零码都算成不可用 |

## 2026-10-22 · 修掉 14 只人设全废的真 bug + 演示图管线打通 ✅

> 上一轮（10-21 夜）结束时桌宠功能是通的，但留了两个我没查完的疑点。这轮把它们挖到底了。

### 1. ★ 根因：人设 slot 写成了错的数据形状（我自己的脚本干的）

`config.json` 里 14 个角色全都长这样：

```json
"球棒狸": { "id": "p_球棒狸", "name": "球棒狸", "displayName": "球棒狸",
            "personality": "...", "speakingStyle": "..." }
```

而 `config-store.ts` 定义的 `CharacterPersonaSlot` 是：

```ts
interface CharacterPersonaSlot { personas: CharacterPersonaEntry[]; activeId: string }
```

于是 `slot.personas` 是 `undefined` → 所有读 `slot.personas.length` 的地方抛
`TypeError: Cannot read properties of undefined (reading 'length')`。

**这个 bug 的可怕之处**：它不报错、不崩、不弹窗。React 里是
`Uncaught (in promise)`，被 catch 吞掉 → 人设解析静默回退到通用兜底，
14 只桌宠说话一个味。上一轮我误以为「AI 对话打通 = 人设也生效了」，
其实只验证了「有回复」，没验证「回复是这只宠物的口吻」。

**谁写的**：`scripts/set_personas.py` —— 我自己 10-21 写的人设注入脚本。
它写扁平对象，而 UI 保存走的是 `{personas, activeId}`，两套形状不一致。

**修法**（三层都要改，只改一层还会复发）：
1. 数据：把 14 个 slot 包成 `{activeId, personas:[entry]}`（备份 `config.json.bak-20261022`）
2. 脚本：`set_personas.py` 改成写正确形状，且能识别并修复旧的扁平数据
3. 代码：4 处读取点全部加 `Array.isArray(slot?.personas)` 兜底
   （`use-proactive-greetings.ts` / `chat-bubble.tsx` ×2 / `pet-menu.tsx` ×2）

### 3. 演示图管线（`scripts/pet_demo_shot.py`）

桌宠窗口是全屏透明置顶，截屏会被别的窗口盖住（踩过两次），
所以演示图必须：**读 canvas 像素 + 读气泡 DOM 文字，在 Python 里自己合成**。

踩到的坑：

| 坑 | 现象 | 根因 |
|---|---|---|
| `Image.open(bytes)` | `UnicodeDecodeError: 0x89` | PIL 把 bytes 当**文件名**去 `os.fsdecode`，0x89 是 PNG 魔数。必须 `io.BytesIO(...)` |
| emoji 变空心方框 □ | 气泡末尾 ⚾ 显示不出来 | 中文字体没有 0x26BE 字形，要单独用 `seguiemj.ttf` + `embedded_color=True` |
| 中文断词 | 「召唤出来」被断成「召唤出 / 来」 | 我自己画的气泡宽度按角色 192px 算，真实 CSS 是 `max-width:320px`。按真实 CSS 还原 + 加中文行首/行尾禁则 |

### 4. 测试工具自身的两个坑（差点误判成产品 bug）

- **CDP socket 超时固定 20s** → AI 对话要等 3~10s，模型慢一点就 `eval: timed out`，
  看着像「人设没生效」。改成 `CDP(url, timeout=120)` 可调。
- **`npx vitest run` 报 "No test suite found"** → 那两个 `*.test.ts` 是 `tsx` 跑的
  独立断言脚本（打印「56 通过 / 0 失败」），不是 vitest 套件。
  正确跑法：`npx tsx shared/pet-physics.test.ts`。

### 6. 判据的教训：不要拿模型的自由度当硬失败

第一版人设判据只看「自称」（本狸/本喵/在下…）。实测 **摸鱼猫三次都没说「在下」**，
但回答「喵~主人来啦，这个点儿才开机，昨晚又加班了吧」明显是它的油滑风格 ——
判据一个词都没命中，报假红。

改法：
1. 标记词放宽到「运气质词 + 自称」（但承认不可能穷举）
2. **加一条强判据**：14 只回答必须**互不相同**。人设若没读到，全部会退化成
   同一段通用兜底 → 回答高度雷同。这条不依赖猜词，比标记词靠谱。

### 修掉的真实 Bug（都是读代码看不出来的）

1. **坐标系错配** — 物理层用「包围盒左上角」语义（上游约定），本项目 `posRef` 存「中心点」
   （容器带 `translate(-50%,-50%)`）。差半个身位 → 落地偏 100px。修后误差 0px。
2. **素材比例假设** — dsh-pet 是 16:9 视频（h=size×9/16），我们是 192×208 像素图（12:13）。
   物理按 9/16 算地面 → 桌宠落地有一半沉在屏幕外。`throwBounds` 增加显式 `height`。
3. **petdex v2 格式** — 4 只社区桌宠是 1536×2288（8×11），底座只认 8×9 → 直接用会画错行。
   导入器自动裁掉底部 2 行转 v1。
4. **Q 弹不能放渲染循环** — 渲染循环 8fps，挤压动画会一顿一顿的。必须单独 60fps rAF。
5. **RESTITUTION 过弹** — 上游 0.78 → 空中弹 15 次持续 2 秒。调到 0.52。
6. **`imageRendering` 硬编码 pixelated** — 那是给像素风准备的，社区插画风桌宠放大后出锯齿色块。
   试过两版自动检测判据（突变率/唯一色数）**都判错** → 改为素材声明 + 用户覆盖。

## 2026-10-12 凌晨 · ★ 球棒狸素材端到端打通（桌宠首次跑通真实角色）

### 1. 卡了半宿的根因：yaw 默认值是反的

昨晚 `render_limao.py` 默认 `--yaw 180`，渲出来全是**背面**（只有爪印和背包，没脸），
一直以为是对中/相机有问题。真相很简单：**模型正面朝 -Y，相机也在 -Y，yaw=0 就是正脸**。

`yaw_probe.py` 本该一早就查出来，但那个脚本是**坏掉的半成品**：

- 文件里有**两段重复的渲染循环**，第二段是重写时残留的；
- 第二段对中用了 `+c`，而它自己的注释就写着「对中的平移符号是 **-c 不是 +c**」；
- 结果 90/180/270 三个朝向全渲成空帧，把第一段的好结果覆盖掉 ——
  表现就是「yaw_90/180/270 三个文件字节数完全相同且 alpha 全 0」。

已重写（只有一段循环 + 渲完断言非空 + 空帧直接 SystemExit），四朝向实测：
**0° 有完整五官（爪印瞳孔 + 吻部），90/270° 侧面轮廓，180° 与 0° 镜像**。
`render_limao.py` 的默认值同步改成 0。

### 2. 自己写的扫描器把自己坑了（判据没校准就拿去判素材）

新增 `scripts/check_frames.py` 扫导引色风险，第一版判据是「饱和度 + 通道相对比较」
的近似式 → **57 帧全部误报**（每帧 3400+ 像素）。

源码 `hatch-pet-host.tsx:194-204` 的 `shouldClearGuidePixel` 其实是**四个固定绝对阈值**组合：

```js
const saturated = Math.max(r,g,b) - Math.min(r,g,b) > 70;
return (r<95 && g>110 && b>110) || (g<95 && r>120 && b>110) ||
       (r<95 && g<110 && b>120) || (r<95 && g>120 && b<110);
```

**教训（第二次栽在同一类坑上）**：判据是尺子，尺子没校准就用，等于用错的尺子改对的东西。
新增 `scripts/cross_check_guide.py` 把源码逻辑用 Node 原样跑一遍对拍：
**阈值邻域穷举 2197 例 + 随机 15 万例，逐像素全部一致**。校准后重扫 → 0 问题。

（`scripts/test_guide_color.py` 早就有穷举+随机测试，但那是**自洽**测试，
抓不到「两边都跑得动但判据不一致」。对拍才有意义。）

### 4. ★ 角色 id 带前缀（差点以为扫描失败）

`config.defaultCharacterId` 我按规格文档填了 `球棒狸`，**结果静默回退到橘猫**。

需要补上前缀规则。（待改）

### 5. 新增工具：CDP 直连桌宠（截图验桌宠根本不可靠）

桌宠窗口是全屏透明置顶（`0,0,2048,1104`），**桌面上任何别的窗口都会盖住它**。
截屏验到的三次都是聊天窗口内容，vision 读出来全是聊天文字 —— 差点据此得出错误结论。

| 脚本 | 作用 |
|---|---|
| `scripts/pet_probe.py` | CDP 连进渲染进程，查角色列表 / 当前 defaultCharacterId / DOM |
| `scripts/pet_shot.py` | **直接读 canvas.toDataURL**（不受遮挡影响）+ bbox/非空像素统计 |
| `scripts/pet_anim_capture.py` | 连拍多帧，按 bbox 变化判定「动画在不在动」+ 抓空帧 |

为此给 `electron/main.ts` 加了 `PET_CDP=1` → `app.commandLine.appendSwitch('remote-debugging-port', '9222')`
（只在显式设该环境变量时生效，打包版永不开）。

**为什么必须直读 canvas**：`pet_shot.py` 优先走 canvas 像素，截屏只作兜底。

### 7. 本轮环境坑

- **bash 重定向与 Windows 程序的路径语法是两套**：
  - bash 自己重定向 → 必须 MSYS 风格 `/e/hsr-pet-extract/x.log`
  - 给 Windows 程序（Blender/PowerShell）传路径 → 必须原生 `E:\...` 或 `E:/...`
  - 混用两种都报 `No such file or directory`（连 `D:/...` 这种半原生也不行）
- PowerShell 在 GBK 控制台下吐中文，`subprocess(text=True)` 用 utf-8 解会抛
  `UnicodeDecodeError: 0xd3` → 一律加 `errors="replace"`，并且**失败时必须打 stderr**
  （第一版把错误吞了，只看到一句 "saved x"，白排查一轮）。
