### 1. ★ 真 bug ①:插件工具拿不到宿主模型(ctx 永远是 None)

```
{"success": true, "watched": [{"visual": "", "reason": "",
  "error": "模型调用失败:'NoneType' object has no attribute 'llm'"}]}
```

- **根因**:`register(ctx)` 里的 ctx 是 `PluginContext`(有 `.llm`),但工具被 agent 调用时,
  `tools/registry.py::dispatch()` **只按 handler 签名过滤注入 kwargs**(task_id/session_id…),
  `ctx` 不在其中 → handler 的 `ctx=None` 默认真是 None。
- **修法(双保险)**:
  1. `__init__.py` 注册时用 `_bind(handler)` 把 ctx 闭包进去;
  2. `tools.py` 加载时 `set_plugin_ctx(ctx)`,handler 里 `_resolve_ctx()` 兜底。
- **验证**:打了一行 `DOUYIN_DBG _understand ctx=PluginContext plugin_ctx=PluginContext`,
  确认模型真的拿到宿主上下文(`agent.log`),验证完已删掉探针。

### 2. ★ 真 bug ②:抽帧落在 `browser-profile/` 里,被 Hermes 安全策略拦

- 旧路径 `profileDir/../douyin-state` = `<hermes-home>/browser-profile/douyin-state`,
  整个 `browser-profile` 被 Hermes 当「真实浏览器快照(含 cookie/登录态)」保护,
  任何工具读那里都被拒:`Access denied: ... is inside the Hermes real-profile browser snapshot`。
- 修法:抽帧/录音统一落到 `<hermes-home>/plugin-data/douyin-pet/captures/cap-<ts>/`。

### 3. ★ 真 bug ③:同一个 profile 并发 / 残留 Edge → 浏览器起不来

实测两种失败:

```
browserType.launchPersistentContext: Failed to launch the browser process.
[pid=xxxx][out] 在已有浏览器会话中打开。
<process did exit: exitCode=0>        ← Playwright 拿不到浏览器
page.goto: net::ERR_ABORTED at https://www.douyin.com/?recommend=1
```

- **根因**:同一个 `user-data-dir` 已有 Edge 会话时,新起的 Edge 会「移交」给旧实例然后自己退出;
  两个 session 同时刷时互相把对方的浏览器/worker 踢掉。
- **修法**:
  - 起浏览器前 `killStaleProfileBrowsers()` 清掉占着本 profile 的 Edge + `Singleton*` 文件,
    失败后清一遍再重试一次;
  - worker 启动时抢 `worker.lock`(pid 文件):主人还活着就明确报
    「另一个刷抖音任务正在跑(pid=xxx),等它结束再试」,主人已死则清锁重来。

### 4. ★ 真 bug ④:worker_bridge 三处竞态(都会长成"worker 没起")

| 位置 | 症状 | 修法 |
|---|---|---|
| `start()` 无锁 | 两个线程同时通过「_proc is None」→ 起两个 worker 抢 9333 端口 | 加 `_start_lock` |
| `_send()` 只判 None | 上一条会话的 `on_session_end` 把 worker 关了 → 下一条报「worker 没起」 | 自动 `start()` 重起 |
| `stop()` 里的 `_send(..., timeout=3)` | 参数签错 → 静默吞异常;且 terminate() 会跳过 Node 的清理 | 直接写管道 + 先等 3s 优雅退出 |

### 4. ★ Windows 上 spawn .cmd 的三个坑(桌宠 agent-bridge)

| 坑 | 现象 | 解法 |
|---|---|---|
| `shell:true` + 多行 prompt | `hermes: 'xxx' is not a 'hermes' command.` —— 换行被 cmd.exe 当命令分隔符 | 显式 `spawn('cmd.exe', ['/c', full, ...args])`,参数用数组传 |

### 1. 三个真 blocker(全部实跑撞出来)

#### ① `get-windows` 原生模块 rebuild 失败

```
• installing native dependencies  arch=x64
• preparing       moduleName=get-windows arch=x64
Error: Could not find any Visual Studio installation to use
    at VisualStudioFinder.fail (.../node-gyp/lib/find-visualstudio.js:122:47)
```

electron-builder 默认跑 `@electron/rebuild`,对每个带原生 binding 的依赖调 node-gyp

**为什么可以跳过**:`get-windows` 是 NAPI 包,自带 `napi-9` 预编译二进制

NAPI 的 ABI 跨 Node/Electron 版本稳定 —— 重新编译不但没必要,
反而会把预编译产物覆盖成 Electron 版本。→ `npmRebuild: false`。

#### ② winCodeSign 解压要建 darwin 符号链接

```
ERROR: Cannot create symbolic link : 客户端没有所需权限 :
  .../Cache/winCodeSign/548258227/darwin/10.12/lib/libcrypto.dylib
• Above command failed, retrying 3 more times
```

「编辑 exe 图标/版本信息」这一步(`win.signAndEditExecutable`)会去下载并解压
winCodeSign 工具包,而那个包里带 macOS 的 **darwin 符号链接**。

**darwin 目录在 Windows 打包里根本用不上**,但 7za 会因为这两个符号链接整体失败
→ 打包 100% 挂。

### 2. 图标:为什么必须挂在 `afterPack`

一开始想「打包完手动跑一次 rcedit」,结果发现**会被下一轮打包冲掉**:

```
第一轮 --dir  → win-unpacked 生成 → 手动补图标 ✅
第二轮 打包   → 重新生成 win-unpacked → 图标没了 ❌
```

因为 **NSIS 安装器打的是 `win-unpacked` 里的文件**,而 NSIS 是在 win-unpacked
**之后**才生成的。手动补得跑两轮,第二轮就把第一轮冲了。

`afterPack` 钩子正好卡在两步中间 —— 补完图标,安装器才去打包含 icon 的 exe。

> ★ 钩子必须写成 `.cjs`:项目 `package.json` 是 `"type": "module"`,
> `.js` 后缀会被当 ES module,而 electron-builder 用 `require()` 加载钩子 →
> `require is not defined in ES module scope`。

### 1. ★ 本轮修的真 bug:探针在骗人

`agent-bridge` 的 `probeBackends()` 是给设置面板看"哪些 agent CLI 能用"的。
它的实现只看**文件在不在**:

```
hermes        ✓ 已就绪:D:\...\hermes.cmd
codex         ✗ 已安装但未登录(缺 ~/.codex/auth.json)
command-code  ✓ 已就绪:D:\...\command-code.cmd      ← 这里在撒谎
claude        ✗ 未安装
opencode      ✗ 未安装
```

**真跑一下 command-code 才知道**:

```
$ command-code -p "hi"
stdout: Updated 1.63.0 → 1.88.0
stderr: Error: Insufficient credits for Command Code.
exit code: 10
```

它**装了、登录了(`~/.commandcode/auth.json` 存在)、但额度耗尽**。
静态探针查不到账号状态 —— 额度不是文件,只有真跑才知道。

用户看到的却是"✓ 已就绪",点下去才炸。**这比直接报错更糟**:
设置面板把不可用的后端显示成可用的,用户会以为是自己的用法问题。

> 讽刺的是,`agent-bridge.ts` 自己的文件头注释就写着
> "**可用性必须实测**,不能只看 `which`" —— 但 probeBackends 恰恰只做了静态检查。

#### 修法:让运行结果反哺探针

1. **新增 `detectUnavailableReason(text)`** —— 认出三类"用不了"的信号:
   - 额度不足:`insufficient credits` / `quota exceeded`
   - 未登录 / 认证失败:`not logged in` / `authentication failed`
   - 需要交互式 TTY:`interactive mode requires a TTY`

2. **新增运行时判定缓存**(`recordRuntimeVerdict` / `getRuntimeVerdict`):
   `runAgent` 结束时按后端 id 记下"这次跑通了"或"这次因为额度挂了 + 具体原因"。
   探针**优先读这份缓存,覆盖静态结论**。TTL 30 分钟 —— 额度不会秒级变,
   但用户可能刚充值,过期后自动回到静态判断。

3. **`command-code` 增加登录态静态预检** —— 缺 `~/.commandcode/auth.json` 就直接报未登录,
   不用等到跑完才失败。

#### 踩坑记录

| 坑 | 现象 | 根因 |
|---|---|---|
| 探针只看文件 | command-code 报"已就绪",实跑退出码 10 | 额度是账号状态,文件里查不到 |
| 错误在 stderr 不在 stdout | `command-code -p "hi"` stdout 只有 "Updated 1.63.0 → 1.88.0" | 自更新提示占了 stdout;真错误在 stderr → 判据要同时看两股流 |
| 漏了 `-p` 参数 | 手动验证时报 "Interactive mode requires a TTY terminal." | `command-code` 不带 `-p` 就是交互模式 → 探针里的 `buildArgs` 才是对的,手测时得跟它一致 |
| 非零退出码不等于"后端不可用" | 任务本身失败也会退出码 1 | 必须先问"是不是额度/登录问题",不能把所有非零码都算成不可用 |

1. **坐标系错配** — 物理层用「包围盒左上角」语义（上游约定），本项目 `posRef` 存「中心点」
   （容器带 `translate(-50%,-50%)`）。差半个身位 → 落地偏 100px。修后误差 0px。
2. **素材比例假设** — dsh-pet 是 16:9 视频（h=size×9/16），我们是 192×208 像素图（12:13）。
   物理按 9/16 算地面 → 桌宠落地有一半沉在屏幕外。`throwBounds` 增加显式 `height`。
3. **petdex v2 格式** — 4 只社区桌宠是 1536×2288（8×11），底座只认 8×9 → 直接用会画错行。
   导入器自动裁掉底部 2 行转 v1。
4. **Q 弹不能放渲染循环** — 渲染循环 8fps，挤压动画会一顿一顿的。必须单独 60fps rAF。
5. **RESTITUTION 过弹** — 上游 0.78 → 空中弹 15 次持续 2 秒。调到 0.52。
6. **`imageRendering` 硬编码 pixelated** — 那是给像素风准备的，社区插画风桌宠放大后出锯齿色块。
   试过两版自动检测判据（突变率/唯一色数）**都判错** → 改为素材声明 + 用户覆盖。
