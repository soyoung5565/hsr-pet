# 星铁模型资产「一比一渲染」调研报告

> 调研日期：2026-10-13 · 方法：multi-search-engine 聚合搜索（豆包Custom/Global + 百度千帆 + Tavily）
> + GitHub API 直读 shader 源码 + 本地贴图实测验证
> 目标：解决「资源已抓到，但渲染效果与游戏内差距非常大」

---

## 〇、一句话结论

**你们不是缺工具，是缺 shader。**

现在用的是「材质推倒重建 + Principled BSDF」，而游戏里跑的是米哈游自研 Toon Shader。
Principled BSDF 里根本没有「冷色偏移阴影」「8 槽材质分层」「脸部 SDF 阴影」这些概念，
所以再怎么调参数也不可能像 —— 这是**方向性错误**，不是参数没调好。

**好消息**：星铁的核心渲染贴图你们**已经导出来了**，只是之前完全没用上。
`Body_LightMap` / `Cool_Ramp` / `Warm_Ramp` / `MaterialIDValuesLUT` 全躺在 E 盘目录里。

---

## 一、根因：游戏渲染管线 vs 你们当前的渲染管线

### 1.1 你们现在做的（错的）

```
FBX → Blender → 清空材质节点树 → 新建 Principled BSDF → 贴图直连 → OPAQUE → Cycles 渲染
```

问题：Principled BSDF 是 **PBR 写实模型**（能量守恒的连续渐变），
而卡通渲染要的是**把连续光照主动压成有限色阶**。两者数学模型相反。

### 1.2 游戏里真正做的（对的）

崩铁 = **延迟渲染的场景 + 前向渲染的角色**，角色每个部位分 **两个 Pass**：

- 第一遍：算 Ramp Diffuse + Rim Shadow Light，存到 RT
- 第二遍：读 RT，做 Specular / Emission / Bloom / Tonemapping 合成

社区逆向分析（知乎《简单复刻一下〈崩坏-星穹铁道〉的角色渲染》）原话：
> "崩铁的场景还是走的延迟渲染，角色前向渲染，只不过角色的每个部位分了两个 pass 渲染"

### 1.3 Pass 全清单（来自 StarRailNPRShader 源码，最权威）

| Pass | 文件 | 作用 |
|---|---|---|
| CharBody | `CharBody.shader` (23K) | 身体 |
| CharBodyTransparent | `CharBodyTransparent.shader` (17K) | **半透明刘海** |
| CharFace | `CharFace.shader` (10K) | 脸部 + 表情 |
| CharFaceMask | `CharFaceMask.shader` (6.7K) | 脸部件遮罩（眉毛穿过刘海靠它） |
| CharEyeShadow | `CharEyeShadow.shader` (4.4K) | 眼睛阴影 |
| CharHair | `CharHair.shader` (13K) | 头发（各向异性高光） |
| Outline | `CharOutline.hlsl` | 描边 |
| Shadow / PerObjectShadow | `PerObjectShadow.hlsl` | **逐物体阴影，同屏 16 个** |
| PostProcess | `PostProcessPass.cs` (18K) | Bloom + Tonemapping |

**注意**：光栅 pass 之外，还有 `CharDepthNormals`、`CharDepthOnly`、`CharMotionVectors`、
`HairDepthTexture`、`ScreenSpaceShadows` —— 全是为角色单独开的管线。

## 二、五大还原要素（按对「像不像」的贡献排序）

### ★★★ 要素1：Ramp 阴影贴图（你们完全没用 ← 最大差距来源）

游戏不用连续的 diffuse 明暗，而是**查表**：

```hlsl
// CharRenderingHelpers.hlsl — GetRampUV()
float ao = lightMap.g;
float material = lightMap.a;           // ← 材质槽 0~7
float NoL01 = NoL * 0.5 + 0.5;         // ← 光照强度归一化

float shadow = min(1.0, dot(NoL01.xx, 2 * ao.xx));
shadow = max(0.001, shadow) * 0.75 + 0.25;
shadow = lerp(0.20, shadow, saturate(shadowAttenuation));
shadow = lerp(0, shadow, step(0.05, ao));   // AO<0.05 永不反光（自阴影）
shadow = lerp(1, shadow, step(ao, 0.95));   // AO>0.95 永远全亮
return float2(shadow, material + 0.05);
```

**实测你们的贴图，完全吻合**：

| 贴图 | 实测 | 对应 shader 含义 |
|---|---|---|
| `Cool_Ramp.png` | **256×16**，R 166-255 / G 130-255 / B 190-255 | X轴=NoL阴影查找，Y轴=8条材质槽 |
| `Warm_Ramp.png` | **256×16** | 同上（暖色调版本） |
| `Body_LightMap.png` | **2048²**，R=高光强度 / G=**AO**(0~102) / B=高光阈值(≈0) / **A=材质ID**(0~66) | `lightMap.g`=AO，`lightMap.a`=槽位 |
| `MaterialIDValuesLUT*.png` | **8×8** | 8 个材质槽各自的参数 |

**暗部为什么是冷蓝紫**（vision 实测确认）：
ramp 图暗部色相从左到右 **粉紫/洋红 → 紫罗兰 → 蓝紫/冷蓝**。
Principled BSDF 的阴影只会往灰黑走，**永远不会出现这种冷紫偏移** → 这是"不像"的最大观感来源。

冷暖混合由 `_RampCoolWarmLerpFactor` 控制（贴图同名参数，默认 1）。

### ★★★ 要素2：脸部 SDF 阴影（面部立体感的来源）

```hlsl
// CharFaceCore.hlsl — GetFaceOrEyeDiffuse()
float3 lightDirProj = normalize(L - dot(L, headUp) * headUp);   // 投影到面部切平面
bool isRight = dot(lightDirProj, headRight) > 0;
float2 sdfUV = isRight ? float2(1 - uv.x, uv.y) : uv;           // 右脸镜像 UV
float threshold = SAMPLE_TEXTURE2D(_FaceMap, sampler_FaceMap, sdfUV).a;  // ← SDF阈值图
float FoL01 = dot(headForward, lightDirProj) * 0.5 + 0.5;
float3 faceShadow = lerp(_ShadowColor.rgb, 1, step(1 - threshold, FoL01) * shadowAtten);
```

用一张 **SDF 阈值图**（FaceMap 的 A 通道）决定脸上哪块该暗，跟头部骨骼朝向无关。
这就是为什么游戏角色的鼻子/下巴阴影永远合理 —— 它不是算出来的，是**预烘焙的几何信息**。

⚠️ 随宠（狸狸猫）的脸是动物脸，SDF 图是否存在需单独确认。若无，可用头骨骼朝向 + smoothstep 近似。

### ★★ 要素3：材质分层 8 槽（不是"一个角色一套材质"）

```hlsl
// CharBodyMaterials.hlsl
int GetCharMaterialId(float4 lightMap) { return clamp(floor(8 * lightMap.a), 0, 7); }
```

**一个身体贴图承载 8 种材质**（金属/布料/皮肤/皮革…），靠 `lightMap.a` 分槽，
每槽有独立的 `_SpecularColor/_SpecularShininess/_RimColor/_BloomColor/...`。
知乎那份对比文档也印证：原神 12-15 层 → 星铁 **20-25 层**（密度提升 60-70%）。

你们现在整只狸狸一套材质 = **8 层压成 1 层**，金属和布料的高光/边缘光完全一样 → 塑料感。

### ★★ 要素4：描边（Inverted Hull + 平滑法线）

```hlsl
// CharOutline.hlsl 关键：顶点沿平滑法线外扩 + Z 偏移
float _OutlineWidth;  float _OutlineZOffset;
DEF_CHAR_MAT_PROP(float4, _OutlineColor);   // 每槽独立描边色
```

**坑（你们已经踩过）**：沿原始法线外扩会在硬边处断裂，必须**另存一套平滑法线**（顶点法线求平均）。
社区方案：顶点法线 XY 存外扩方向、剩下通道存 Z 偏移和宽度。
⚠️ SRMI 的 issue 里明确写了 "broken outlines" —— 描边断裂是这个路线的老大难。

### ★ 要素5：边缘光（RimLight）—— 屏幕空间深度偏移法

```hlsl
// 不是常规 fresnel！是"横向偏移 1 像素再采深度"的屏幕空间技巧
rimWidth *= _ScaledScreenParams.y;                    // 分辨率无关
rimWidth *= unity_CameraProjection._m11 / 2.414;     // FOV 45° 的魔法数
rimWidth *= 10.0 * rsqrt(depth * invModelScale);     // 近大远小
float indexOffsetX = -sign(cross(V, N).y) * rimWidth;
float offsetDepth = LoadSceneDepth(clamp(pos + offsetX));
float intensity = smoothstep(0.12, 0.18, (offsetDepth - depth) * invModelScale);
float fresnel = pow(max(1 - NoV, 0.01), edgeSoftness);
```

另有 `RimShadow`（背光侧的暗边）、`DitherAlpha`（4×4 Bayer 抖动透明，半透明刘海用）。

## 四、三条可选路线（按推荐度排序）

### 🥇 路线 A：Unity + StarRailNPRShader（还原度最高，★★★★★）

**原理**：这是社区公认**最接近游戏本体**的复刻（981★，作者根据游戏逆向实现）。
你们已经有 FBX + 全部贴图，导进 Unity 挂这个 shader 即可。

**步骤**：
1. 装 Unity 2022.3 + URP（注意：**必须线性色彩空间**）
2. `Window > Package Manager > Add package from git URL`
   → `https://github.com/stalomeow/StarRailNPRShader.git`
3. URP Asset 里 RenderingPath 设 **Forward/Forward+**，关 **Depth Priming**，
   加 Renderer Feature = `StarRailRendererFeature`
4. 模型根节点挂 `StarRailCharacterRenderingController` 组件
5. 按 MaterialID LUT 逐槽设 8 组材质参数
6. 贴图导入设置（**这是最容易翻车的地方，作者专门警告过**）：
   - 数值类贴图（LightMap/Mask）**取消勾选 sRGB** → 保持线性
   - Ramp 图**必须关闭 Generate Mipmaps** + Wrap=Clamp + Compression=High Quality
     （否则阴影交界会出现难看的锯齿，会被误判成 shader 写错了）

**优点**：还原度最高、有自动化流程（平滑法线/材质生成）、能渲动画
**缺点**：要装 Unity（~25G，D 盘只剩 43G ⚠️ 需先清空间或装 E 盘）；渲染输出后再转精灵表

### 🥈 路线 B：Blender + Goo Engine + StellarToon（次高，★★★★）

**原理**：`festivities/Blender-StellarToon`（300★）是**专门为 Blender 复刻星铁 shader** 的，
已汉化适配，直接对上你们的 Blender 管线，不用换引擎。

**步骤**：
1. 装 **Goo Engine**（Blender 的 NPR 定制分支，免费版从 Patreon/官网下；
   也可用 Blender 3.6 + Moo Shader 插件的组合）
2. 导入 StellarToon 节点组
3. 套 `foxlynna/xiaojubao-honkai-star-rail` 插件 —— **专门批量给星铁模型套材质和描边**
   （该插件的"角色配置文件"已有人配好 55 个角色，可参考格式）
4. 按各角色配置贴图 + 调描边

**优点**：不换引擎、渲染完直接进现有拼表管线、社区有中文教程（B站"十分钟速通"）
**缺点**：作者自己声明 "isn't meant to be 100% accurate"；依赖 Goo Engine 商业分支

### 🥉 路线 C：手写 Blender 节点（最可控，工作量最大，★★★）

按 `GetRampUV` + `GetRampDiffuse` 的公式，在 Blender 着色器编辑器里 1:1 复刻：
1. Ramp 查表节点（256×16，按 `lightMap.a` 选行、按 NoL 选列）
2. AO 参与的三段 lerp（照抄那 4 行 `step/lerp`）
3. 冷暖 ramp 混合
4. 每槽 8 组参数分组切换
5. 屏幕空间边缘光（较难，需要 Geometry/渲染层技巧）
6. Inverted Hull 描边 + 平滑法线

**优点**：完全可控、无外部依赖
**缺点**：脸部 SDF 和屏幕空间边缘光在 Blender 里实现成本高

### 📌 补充路线 D（保底）：录屏抠像

如果时间紧，**直接从游戏里录屏 + SAM2 抠像**是"视觉上一比一"的兜底 —— 因为它就是游戏本身的像素。
缺点：需要干净背景、无法控制角度/动作。但作为桌宠精灵表（9行固定机位），其实**完全够用**。

## 五、如果走路线 A/B，必须知道的额外知识

### 5.1 表情是三层叠加（Blender 里也要做）

shader 参数里有 `_ExCheekColor`（腮红）、`_ExShyColor`（害羞）、`_ExShadowColor`、`_ExEyeColor`，
配合 `_ExpressionMap` 贴图 → **表情不是画在脸上的，是运行时乘上去的**。
强度由 `_ExCheekIntensity/_ExShyIntensity/_ExShadowIntensity` 控制。
你们现在只做了"重铺一个睁眼 sprite"，这解释了为什么表情看着僵硬。

### 5.2 鼻线（Nose Line）

```hlsl
float3 FdotV = pow(abs(dot(headForward, V)), _NoseLinePower);
texColor.rgb = lerp(texColor.rgb, texColor.rgb * _NoseLineColor.rgb, step(1.03 - faceMap.b, FdotV));
```
正面视角时鼻子正对镜头那条竖线加暗 —— 猫脸的立体感靠它。

### 5.3 半透明刘海（角色最有辨识度的特征）

`CharBodyTransparent.shader` + `HairDepthTexture` + `_MaxEyeHairDistance`：
**透过前面刘海能看到眉毛/额头**。这是星铁角色"精致感"的重要来源，随宠刘海少，优先级可降。

### 5.4 色彩管理（容易被忽略）

- Unity 侧：**必须线性色彩空间**
- 数值贴图（LightMap/Mask）：**取消 sRGB**；颜色贴图（BaseColor/Ramp）：保留 sRGB
- Blender 侧：Filmic/AgX 会压掉卡通高饱和 → **建议 Standard + sRGB**，或 AgX 但提高 saturation
- 后处理：游戏是**自定制的 Bloom + Tonemapping**（`CustomBloom.shader` / `CustomTonemappingMode`），
  不是 Unity 默认值 → 用默认后处理渲出来色调也会偏

### 5.5 光源设置

游戏 = 1 盏平行光（主光）+ 逐物体阴影 + 环境光。
`_RimColor` 的边缘光宽度是**屏幕空间像素量**（`width/2000`），所以**渲不同分辨率宽度会变** → 渲染分辨率要和最终精灵表一致。

## 八、附：为什么没走 RenderDoc / 抓帧路线

你们转述的"抓包抓到了"路线（RenderDoc/Ninja Ripper）在本项目里**优先级更低**：

- 崩铁 PC 走 D3D11，反汇编出的 DXBC 汇编**无法直接反编译回可读 HLSL**（社区都在猜变量名，
  知乎原文："根据变量名和计算方式猜，如果不确定自己猜得对不对，可以手动写个简单的Shader验证"）
- 我们已经有 **StarRailNPRShader 的干净 HLSL 源码**（社区基于游戏实现 + 实测调参），
  比从汇编猜**更准确且可读**
- 抓帧唯一不可替代的价值是**读取运行时真实参数值**（如具体 lightmap 常数）。
  如果后续路线 A/B 调参还差一点，可以用 RenderDoc 抓一帧游戏内角色展示界面的
  draw call 参数做对拍 —— 这是**最后的校准手段**，不是第一步
