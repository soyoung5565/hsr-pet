# Hermes 手机/桌面双后端问题 · 诊断结论（2026-10-12）

## 现象
手机（Hermes mobile，Tailscale 100.106.167.85 → 电脑 9119）打开电脑上正在跑的会话时：
1. 提交消息报 `Error (prompt.submit): JsonRpcError(code=4090, SESSION_NOT_OWNED)`
2. AI 已回复到第 10 条，手机只显示第 1 条

## 根因（已用运行时证据确认，非推断）
同一台机器跑着**两个独立的聊天运行时**，共用同一个租约表，但内存会话表各自独立：

| pid | 命令 | 监听 | 使用方 |
|---|---|---|---|
| A | `hermes serve --host 127.0.0.1 --port 0` | 127.0.0.1:<ephemeral> | 桌面 Hermes |
| B | `hermes dashboard/serve --host 0.0.0.0 --port 9119` | 0.0.0.0:9119 | 手机 |

共享文件：`D:\hermes-data\runtime\active_sessions.json`（跨进程会话租约）

- 问题①：桌面 pid 持有会话租约 → 手机所在运行时 B 申请同一租约被拒 → 4090 SESSION_NOT_OWNED
- 问题②：B 没有那个活会话，`session.resume` 同样被拒 → 只能拿 state.db 快照 → 只显示第一条

## 合并两个后端为何失败（关键，勿重复踩）
理论上让桌面 attach 到 9119 即可合并。实测**走不通**，原因链条：

1. 手机要从 Tailscale 连进来 → 必须绑 `0.0.0.0`
2. `hermes_cli/web_server.py::should_require_auth`：任何非 loopback 绑定**强制**开认证（2026-06 加固，`--insecure` 已成 no-op）
3. 开了认证 = gated 模式 → `hermes_cli/web_server_chat.py::_ws_auth_reason`
   在 gated 模式下**只接受** `?ticket=`（浏览器 30s 票据）或 `?internal=`（仅 server 自拉子进程）
4. 桌面 attach 握手的 `probeGatewayWebSocket` **只会发 `?token=`**（进程内 token）
5. → 必然被拒 → 桌面每次启动都重新 spawn 私有后端

**证据**：`D:\hermes-data\logs\desktop.log{,.1,.2}` 中 `[attach] ... rejected the session token on /api/ws`
共 20 次，跨 2026-09-30 → 10-12，**成功 0 次**（"attached to the running Hermes backend" 命中数为 0）。

## 升级到 0.21.7 是否修好了？—— 没有
- 09-29 的 update 确实引入了 attach 机制（`host-backend-attach.ts` 等 4 个文件旧版不存在）
- 升级到 origin/main（eefdfe0692 / 0.21.7）后，`_ws_auth_reason` 新增了第三条凭证：
  `?token=` 携带**用户会话 access token**（走 `_verify_access_token`）
- **但**新 `host-backend-attach.ts` 仍然发 `?token=<published/进程内 token>`（实测全文无 ticket/accessToken 逻辑）
- 实测：新后端 0.21.7 + 发布 token → WS 探测 **ERROR**；审计日志记 `token_auth_failure / session_token_invalid`
- 结论：上游修的是**「远程桌面连接（token 模式）」**这条路，不是**「同机 attach」**这条路
