## 0. 结论速览（先看这里）

1. **"三转二"不需要建模**。所有桌宠框架最终消费的都是 **2D 帧序列**；有两条路：**A 录屏抠像**（最快，用你现有素材）和 **B 提取游戏模型→Blender 渲染**（质量上限高，你机器上星铁 PC 客户端已装，可行性高）。
2. **"功能远比 petdex 多"的现成项目已经很多**，按形态分四大类（详见 §3、§4）：
   - 养成+创意工坊型 → **VPet**（最强，200+ 动画、投喂摸头爬墙、工坊生态）
   - 经典桌面行为型 → **Shimeji 系**（爬窗/扔窗/分裂，行为全由 XML 定义）
   - AI 陪伴型 → **Open-LLM-VTuber / live2dpet / NyaDeskPet / Desktop-pet**（LLM 对话、语音、看屏幕、插件）
   - 轻量状态型 → **petdex / LLMPET / BongoCat**（精灵表状态映射 / 输入联动）
3. **三条可执行路线**（见 §7）：① fork 现成 Electron 项目改造（如 Desktop-pet，素材天然兼容）② 基于 VPet 做 Mod（功能开箱即得，素材要按 VPet 规范重做）③ 自研轻量核心+抄各家设计（最自由）。
4. 素材规格**取决于目标框架**，先看 §6 对照表再决定以什么规格制作母版。

## 2. 素材管线：回答"怎么做三转二、要不要建模"

### 2.1 先给结论

**不需要自己建模。** "三转二"的本质 = 把 3D 角色落到 2D 帧序列。对随宠有两条主路线，外加一条兜底：

### 2.2 路线 A：录屏 → 抠像 → 帧序列（推荐先跑通）

| 步骤 | 工具/做法 |
|---|---|
| 1. 录制 | 游戏内对每个动作单独录制：**固定镜头、背景尽量干净、60fps、让宠物在画面里尽量大**（拍照模式/互动界面可用）；每个动作录足一整圈循环 |
| 2. 抠像 | **SAM 2**（点一下自动跟踪整段视频，逐帧出掩码）→ 边缘精修 **BiRefNet / VideoMaMa**；背景足够干净时简单色键即可 |
| 3. 抽帧 | ffmpeg 按目标帧率抽帧（按框架需求的帧数重采样，如 6/8/12 帧/动作） |
| 4. 整理 | Python(Pillow) 对齐锚点、裁切、缩放、命名 → 打包成目标格式 |
| 5. 打包 | 按目标框架规格输出（见 §6） |

- 优点：用现有素材、链路短、一周内能看到成品。目标尺寸小（桌宠在屏幕上只有几百像素），录屏分辨率通常够用。
- 缺点：只有录过的角度/动作；边缘（毛发）抠像质量是主要风险点，需要 1-2 个动作实测。
- 已就绪：工作区 venv + `tools/inspect_sheet.py`（精灵表检查工具已写好）。

### 2.3 路线 B：提取游戏模型 → Blender 渲染（质量上限最高）

| 步骤 | 工具/做法 |
|---|---|
| 1. 解析本地游戏文件 | **AnimeStudio**（Hoyoverse 版 AssetStudio，社区在用）或 **AssetRipper**——纯离线解析已安装的游戏资源，**不注入游戏进程、无封号风险** |
| 2. 提取模型+贴图 | 在资源里定位随宠模型（角色/宠物 prefab，FBX/网格+贴图） |
| 3. （动画）| 骨骼动画（AnimationClip）能否完整导出**需要先做可行性验证**——这是本路线唯一的不确定点，建议先拿一个角色跑通再说 |
| 4. 渲染 | Blender + 崩铁风格材质：社区已有 **StellarToon**（festivities/Blender-StellarToon，仿崩铁 shader）与 **xiaojubao 插件**（批量上材质/描边，含 55 角色配置）；固定机位渲染**透明背景 PNG 序列** |
| 5. 后期 | 同路线 A 的第 4-5 步 |

- 优点：任意角度、任意时长、画质完全可控；动作直接从游戏数据来，最忠实。
- 注意：**不要用 3DMigoto/SRMI 这类注入方案在官服上跑**（作者明确只建议私服；离线解析方案不受影响）。
- 备选模型来源：社区 MMD 模型（模之屋等）——但随宠这种新宠物大概率没有现成的，先用游戏文件解析。

### 2.4 路线 C：只有截图（兜底，不推荐）

静态图没有动作信息。可做：图标/配色参考、AI 图生视频补帧（质量不可控，动作是"编"的不是"设计好的"）。仅当 A、B 都失败时考虑。

### 2.5 母版规格建议

无论目标框架选哪个，建议先产一套"母版"：

- **512×512 透明 PNG 序列，每个动作 12-24 帧，命名 `<动作>_001.png ...`**
- 再由脚本按各框架要求降采样/重排（帧数、尺寸、打包格式都可以脚本化）

## 4. 重点解剖（实现方法层面）

### 4.1 VPet —— "功能最多"的标杆

- **工程结构**（官方 README）：`VPet-Simulator.Windows`（桌面端）、`VPet-Simulator.Core`（核心库，可嵌进任何 WPF 程序）、`VPet-Simulator.Tool`（MOD 工具，含"图片帧生成"）、`VPet.ModMaker`（独立 MOD 制作器，Steam 免费，“0 门槛”）。
- **动画系统**：`Graph` 渲染体系——`IGraph`（动画接口）/ `GraphCore`（显示核心）/ **`PNGAnimation`（帧动画组件）** / `Picture`（静态）/ `FoodAnimation`（前中后三层"夹心"动画，用于喂食等）。
- **行为与玩法**：动画量 32 种 × 4 状态（含生病等）、投喂、摸头、提起、爬墙、工作时钟（WorkTimer）、消息气泡（MessageBar）、点击工具栏（ToolBar）。带存档系统（养成数据）。
- **MOD 机制**（关键）：**无需写代码**——动画、物品/食物、工作、文本、主题、代码插件都能通过工坊扩展；插件甚至能加新显示方案（l2d/spine）和新功能（闹钟等）。社区口径：MOD 本质 = "一组动画帧图 + 一份文本配置（.lps）"，示例模组目录 `pet/vup/vup.lps`，**帧图建议 500×500**（细节以 ModMaker Wiki 为准，选定路线后专题深挖）。
- **能抄什么**：帧动画配置的思路（图+配置解耦）、工坊式扩展设计、喂食"三层动画"这种表现小技巧。
- **风险点**：默认角色是人形（萝莉丝），随宠是四足小动物——VPet 的行为集（摸头/提起/爬墙）在四足形态上的适配要重做动画；要产出大量动画帧（每个行为 × 状态 × 帧数），素材工作量是本路线最大的成本。

### 4.2 Shimeji 系 —— "桌面行为"最强

- **行为系统**：动作与行为链完全由 **XML 定义**（可做爬窗、扔窗、分裂、瞬移等复杂行为）；社区文档齐全（ShimeCentral 有帧编号对照、行为编辑、投射物、热区等进阶文档）。
- **素材规范**：一个角色 = 一个 `img/<角色>` 文件夹 + **`shime1.png` ～ `shime46.png` 共 46 张固定语义帧**（站/走/爬/被拖/落下等，对照原版 `img/Shimeji` 的姿势）+ 一份 conf；托盘图标 `icon.png`。
- **生态现状**：原版 → Shimeji-ee → Kilkakon → DalekCraft → 各种 fork；`ngoc-thu/shimeji` 做了 Win10/11 适配 + 图形化设置；`VShimeji` 性能改进。
- **能抄什么**：行为系统设计（XML/数据驱动，天然适合"抄一套简化版行为集"）；"爬窗口边缘、扔窗口"这些经典桌面互动。
- **风险点**：Java 技术栈；46 帧语义固定，对四足宠物的重映射工作量大且帧数少、表现力有限；无 AI 扩展。

### 4.3 Open-LLM-VTuber —— AI 语音伴侣标杆

- **形态**：Python 后端（LLM/ASR/TTS 插件式，可全离线）+ Web/Electron 前端；WebSocket 连接。
- **桌面宠物模式**（官方文档）：透明背景、全局置顶、**鼠标点击穿透（非交互区不挡操作）**、拖拽移动、滚轮缩放、**点击触发动作**、**视线跟随鼠标**；窗口模式与宠物模式共享上下文，托盘可切换。
- **功能面**：实时语音对话（可打断）、语音唤醒、视觉感知（看屏幕）、唱歌、完整电脑控制等——"功能远比 petdex 多"的典型。
- **现状**：v2 正在重写（v1 继续修 bug）。
- **能抄什么**：宠物模式窗口的全部交互清单（穿透/拖拽/缩放/视线跟随）；如果之后想做语音对话，这是最省事的底座。
- **风险点**：素材走 Live2D 模型路线（帧序列不直接支持），除非自写渲染层。

### 4.4 live2dpet —— "Python 全能"参考蓝图（架构最完整）

- **四进程架构**：前端（PySide6 + OpenGL 渲染）/ LLM 后端 / TTS 后端 / 监控后端，**ZeroMQ**（REQ/REP + PUB/SUB + 独立健康检查端口）通信。
- **功能**：LLM 对话（OpenAI 兼容，多种供应商）、**情绪感知 TTS**（8 种情感，切换语速/提示词）、系统监控（CPU/内存/电量…）、**屏幕视觉分析**、**主动搭话**（边缘触发：电量低/CPU 高/切换应用）、**立即吐槽**、随机睡眠、毛玻璃设置面板。
- **细节设计**：情感提取 6 层回退解析、对话历史滑窗+摘要压缩、流式输出、多进程健康监控、纯本地 TCP 不对外暴露。
- **能抄什么**：几乎是一份"重交互桌宠"的完整工程答案——进程划分、IPC、主动行为触发逻辑、历史管理。**如果走自研，这份架构直接可参考**；素材层把 Live2D 换成帧动画渲染即可。
- **风险点**：Live2D 素材路线 + 单作者项目，代码质量需自评。

### 4.5 NyaDeskPet —— 插件化 Agent 架构

- **架构**：前端与后端 Agent **WebSocket 完全解耦**（任何 WS 客户端可接入）；Agent 核心是 **Pipeline 架构**——消息处理分阶段（思考、工具调用、回复…），每阶段可注册多个 Handler 插件；**插件管理 + 插件工作鉴权**。
- **交互**：触碰反应系统（按部位启用/禁用）、TTS 口型同步、流式音频。
- **文档**：USAGE / API / DEVELOPMENT / PLUGINS / AGENT_PLUGINS 全套（想深挖插件机制可直接看文档）。
- **能抄什么**：想给桌宠做"插件生态"或"AI 能力可扩展"，这的 Pipeline 设计是现成答案。

### 4.6 Desktop-pet（git2968） —— 与我们的素材"天然兼容"

- **技术栈**：Electron 33 + React 18 + PIXI.js + pixi-live2d（Windows 向）。
- **双素材支持**：① Live2D Cubism 4 模型；② **Codex hatch-pet 精灵表（`pet.json + spritesheet.webp`）**——和 Hermes/petdex 同格式。目录：`app/hatch-pet/<角色>/`、`app/live2d/<分类>/<模型>/`。
- **功能**：AI 对话气泡（OpenAI 兼容接口可自填）、角色 Persona/人设、**情绪联动表情与动作**、MCP 工具 + Agent Skills（读屏/读文件/联网）、Vosk 离线中文语音输入、托盘菜单、隐藏、开机自启、缩放、位置锁定。
- **意义**：**它把"精灵表桌宠 + AI 对话 + 工具调用"已经拼好了**。我们把随宠精灵表塞进去就能立刻得到一个"会聊天、能语音输入、有工具"的随宠；缺的"桌面行为/养成互动"在这个 Electron 里补出来也不难（PIXI 渲染层 + 加逻辑）。
- **风险点**：较新项目（成熟度/长期维护未知）；默认面向 Codex 生态的 UI 文案可改。

### 4.7 其他值得知道的

- **BongoCat（ayangweb）**：Tauri（Rust）+ 前端，输入事件（键盘/鼠标/手柄）实时驱动动作，透明置顶圆角、自定义 Live2D、MIT、离线——"键盘联动"思路可借鉴。
- **LLMPET**：Electron + 本地 HTTP server + agent hooks（含"等待授权"阻塞钩子）+ 状态机 + token 计量。想把桌宠和"agent/程序状态"联动，这套 hook 架构可抄。
- **MiniCPM-Desk-Pet**：本地 LLM（模型跑在本地）+ 桌宠主题（待机/工作/拖拽/迷你模式动画）+ 气泡；追求"全离线对话"可参考。

## 6. 素材格式对照表（母版 → 各框架）

| 目标 | 需要产出 | 规格 | 适配工作量 |
|---|---|---|---|
| 通用母版 | 透明 PNG 序列 | 512×512，12-24 帧/动作 | 一次制作 |
| VPet Mod | 帧图 + .lps 配置 | 帧图建议 500×500；行为集参照 VPet 动画列表 | 高（动画重新编排+补帧） |
| Shimeji | shime1-46.png + conf | 46 张固定语义，对照原版姿势 | 高 |
| 精灵表（Desktop-pet/petdex/Codex） | spritesheet.webp + pet.json | 1536×1872（8×9，192×208/格），9 状态行、每行帧数 6/8/8/4/5/8/6/6/6、行序 idle/跑右/跑左/挥手/跳/失败/等待/跑/思考 | 低（脚本从母版打包） |
| 自研 | 任意帧序列 | 自定义 | 低 |

> 实际"游戏里能录到的动作"（待机/移动/互动/表情等）与上表各框架动作集的缺口，需在制作前做一次**动作映射表**（哪些直接映射、哪些镜像复用、哪些要合成/省略）——这是下一步的具体工作。

## 7. 三条可行路线（建议）

### 路线 ①：fork 现成 Electron 项目改造（推荐起步）
- 首选对象：**Desktop-pet（git2968）**——精灵表素材天然兼容 + AI 对话/MCP/语音已就位；次选 NyaDeskPet（插件架构更好，但要 Live2D 素材或自写帧渲染）。
- 得到：一个能立刻装随宠、会聊天、可扩展的桌宠；再逐步加"桌面行为/养成互动"。
- 优点：站在别人肩上，符合"用已有项目改"；素材管线产出直接可用。
- 缺点：受项目架构约束；两个项目都较新，需要评估质量。

### 路线 ②：基于 VPet 做 Mod（功能开箱最多）
- 随宠做成一款 VPet 模组：投喂/摸头/工作/工坊/插件立刻全有。
- 优点：不用写代码；功能量级直接拉到"远超 petdex"。
- 缺点：四足宠物与 VPet 行为集的适配成本最高（要产大量动画帧）；受 VPet 玩法/UI 框架约束。

### 路线 ③：自研轻量核心（最自由、工作量最大）
- 技术栈候选：Electron（素材/生态最好抄）、PySide6（与 live2dpet 同栈、你熟悉 Python）、Tauri（最轻）。
- 设计直接拼装各家方案：Shimeji 的行为系统 → 简化行为树；VPet 的帧动画配置 → 配置驱动；LLMPET 的状态映射；live2dpet 的主动搭话/监控逻辑。
- 优点：完全自主，素材母版直用；缺点：从窗口层到行为层全部要自己搭。

**推荐**：如果"AI 对话"是必需项 → 路线 ①（Desktop-pet 起步）；如果"养成互动功能多"是首要 → 路线 ②（VPet Mod）或 ③ 后期自研；如果两者都要且愿意投入 → ① 起步 → 逐步把 ②③ 的设计搬进来。
