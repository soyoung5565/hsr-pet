## 二、两个值得抄的东西

### 2.1 petdex —— 素材生态（★ 最大收获）

**关键发现：petdex 的宠物包格式 = Codex hatch-pet 格式 = 我们底座的资源契约。**

```
1536 × 1872 = 8 列 × 9 行,单帧 192×208 RGBA
9 行语义: idle / running-right / running-left / waving / jumping
          / failed / waiting / running / review
```

和 `shared/hatch-pet-behavior.ts` 的 `HATCH_PET_ROWS` **逐项一致**。
我们辛苦做的 3D 提取 + 拼表管线,产出的是同一格式。

→ 所以 petdex 的 **5087 只社区桌宠** 可以零转换直接用。
→ 已写 `scripts/import_petdex.py` 一键导入。

**★ v2 格式陷阱**：petdex 有两种规格
- v1: 1536×1872（8×9）—— 我们支持
- v2: 1536×2288（8×11）—— **前 9 行语义与 v1 相同**,多出的 2 行是「留给消费客户端的额外动作」

直接把 v2 当 v1 用 → 渲染端按 8×9 采样会算错行,画面乱。
→ 导入器自动裁掉底部 2 行转 v1。

### 2.2 dsh-pet —— 运行时行为层（★ 功能参考）

它把桌宠做成了「三件套」：**① 提示词配方 → ② 素材生成链 → ③ 插件成品**。

**① 提示词配方**（`prompts/桌面宠物 10 秒动作提示词.md`，291KB）
- 绿幕规范：16:9、纯 #00FF00、头顶 20% / 脚底 85% / 左右 25%~75%
- 画幅安全红线：任意一边留 10%
- 每个动作按秒分解（0~3s / 3~7s / 7~10s），末帧必须回到首帧标准站姿
- 「无→有→无」道具闭环：道具必须由角色魔法手势从虚到实生成，结束前消散

**② 素材生成链**（`scripts/`，Python + ffmpeg）
- `chroma_step02.py` — HSV 色相判定抠像（只认绿方向，蓝/白/红永不误抠）
- `normalize_step03.py` — 整帧等比缩放 + overlay 平移，统一到 2160×1215，脚底对齐
- `fill_nn.py` — scipy 最近邻水印填充
- `check_alpha.py` — 验证 HEVC-with-alpha 产物真有 alpha 层

**③ 运行时功能**（本项目已移植/待做）
- ✅ **抛掷物理**（已移植，见下）
- ✅ **动作点播**（已做：右键 → 动作 → 9 行任选）
- ⬜ **屏幕漫游**（部分做了：几何随尺寸缩放；缺「探测空间、不走出屏幕」的多屏逻辑）
- ⬜ **多开同屏**（多只桌宠独立大小位置 + 互撞）
- ⬜ **碎碎念 / 余额动画 / 系统通知**
- ⬜ **HTTP + Cordis 双通道对外接口**（给别的插件驱动桌宠）

**它的物理层**（`dsh-pet/src/shared/physics.ts`，MIT，纯函数无 DOM）已完整移植到
`Desktop-pet/app/shared/pet-physics.ts`，56 项单测全过。

## 三、对本项目的决策

| 项 | 决策 | 理由 |
|---|---|---|
| 底座 | **不换**，继续用 `git2968/Desktop-pet`（Electron+React+PIXI） | 底座已跑通、有 AI 对话/记忆/主动搭话/长期记忆，dsh-pet 是插件不是 App |
| 素材 | **接入 petdex 生态**（5087 只） | 格式完全一致，零转换；已导入 11 只 |
| 物理 | **移植 dsh-pet 的** | MIT + 纯函数 + 有测试；自己重写会踩同样的坑 |
| 素材生成 | **参考它的提示词配方**，但走 AI 视频生成（Agnes Video）而非豆包 | 我们有 AGNES_API_KEY；配方可直接抄 |
| 渲染格式 | **保持 8×9**，导入时把 v2 裁成 v1 | 底座契约是 8×9 |

## 四、本轮实测抓到的真实 Bug（都是「读代码看不出来」的那种）

1. **坐标系错配**（最隐蔽）
   物理层用「包围盒左上角」语义（上游约定），而本项目 `posRef` 存的是**中心点**
   （容器 CSS 带 `translate(-50%,-50%)`）。差半个身位 → 落地时整体偏 100px。
   实测：修正后落地误差 0px。

2. **素材比例假设**（第二个隐蔽坑）
   dsh-pet 素材是 16:9 视频（h = size×9/16），我们是 192×208 像素图（12:13）。
   物理层按 9/16 算地面 → 地面高 100px → 桌宠落地有一半沉在屏幕外。
   修法：`throwBounds` 增加显式 `height` 参数。

3. **Q 弹动画不能放渲染循环**
   渲染循环按 fps 切帧（8fps），8fps 下的挤压是「一顿一顿」的，没弹性。
   Q 弹必须单独跑 60fps 的 rAF。

4. **RESTITUTION 要调**
   上游 0.78 → 桌宠被甩上去后在空中弹 15 次、持续近 2 秒，手感太弹。
   本项目调到 **0.52**：反弹次数约减半，仍保留弹性。

## 五、测试基建（沉淀教训）

本轮写了一套 CDP 端到端测试，**过程中出了三次「假绿」**，都固化成了检查项：

| 假绿 | 症状 | 根因 | 修法 |
|---|---|---|---|
| v1 巡检 | 14 只「全正常」 | 改 config 切不了角色（React state） | 走真实 UI 点击 + 断言当前角色 |
| v2 巡检 | 还是「全正常」 | 帧数从 **canvas** 读，但 canvas 只有一帧 | 读**精灵表** |
| v3 巡检 | 11 只 404 | 从路径猜 `pet://` host 猜错了 | 用 `character.source` 决定 host |

> **教训：判据必须对着真实被测对象，且必须验证被测对象确实变了。**
> 「看起来通过了」的测试比没有测试更危险。

现存脚本（`scripts/`）：
- `import_petdex.py` — 从 petdex.dev 导入社区桌宠（自动 v2→v1）
- `pet_physics_e2e.py` — 抛掷物理端到端（CDP 驱动真实鼠标事件）
- `pet_action_e2e.py` — 动作点播端到端
- `pet_batch_check.py` — 全部精灵表批量体检
- `pet_switch_verify.py` — 真实 UI 切换 + 动画验证
